# Sidebar Row Layout

Capsule-style sidebar with state-aware rounded borders, dynamic heights, and badge overlays.

## User-Facing Behavior

- Every thread row is drawn inside a rounded capsule (`AlwaysEmphasizedRowView`).
  - **Selected**: accent-colored border and fill.
  - **Completion (unread)**: green border and fill.
  - **Waiting for input**: orange border and fill.
  - **Default**: regular thread capsules show their section color as a solid 4pt-wide diagonal band crossing the top-right corner at 45°. The band's center meets the top and right capsule edges 12pt from the mathematical corner, and all four vertices lie directly on those edges. It uses the section color at 40% opacity, increasing to 100% when selected. The marker remains visible for completion, waiting, rate-limit, pop-out, context-menu, and busy states. It renders above the capsule fill but below both the static border and busy animation. Main worktrees do not use it.
- Status badges are flat and borderless inside a full-width in-capsule status row anchored near the bottom of the thread capsule. Vertical content follows an even `8pt top → text rows → 8pt → status row → 8pt bottom` rhythm. The leading workflow group orders priority, Jira status, then combined PR/MR number-and-status. PR/MR and Jira status badges use 9pt medium-weight text in their semantic color over a 10%-opacity tint of the same color. Badge text is strongly lightened toward white in dark appearance and darkened toward black in light appearance while retaining its semantic hue. The trailing local-state group orders rate-limit, Jira-sync, Keep Alive, hidden, activity, stopped-session, favorite, then pinned indicators. The final four form a stable `activity → stopped sessions → favorite → pinned` group. The red `xmark.circle` stopped-sessions indicator appears only when every tmux session for the thread is inactive and explains that selecting a tab recreates it. Keep Alive always shows its shield when explicitly enabled, including on pinned threads. The row follows the same leading and trailing content rails as the text above it. Hidden threads use a dimmed `eye.slash.fill` indicator; the Jira-sync badge uses the colored `JiraIcon` brand asset (not template-tinted) and appears whenever the release-available per-thread "Sync description and priority from Jira" toggle is enabled, independently of the debug-only project/section Jira sync feature.
- Rate-limit badges can show a tiny 2pt red corner dot to indicate a directly-detected local source (non-propagated marker) for that agent on this thread.
- Activity uses a compact symbol immediately before the stopped-session, favorite, and pinned indicators. Busy threads show a colored indeterminate progress indicator only after 1 hour (yellow for 1–5 hours, orange for 5–24 hours, red after 24 hours). Stale threads show a `zzz` symbol only after 7 days (yellow for 7–14 days, orange for 14–30 days, red after 30 days). Main worktrees never show the stale symbol. The activity symbol uses the same appearance-aware semantic foreground calculation as the former text badge. Hover tooltips and right-click actions retain the precise `Busy for …` / `Last activity: … ago` behavior.
- **Priority indicator**: Optional borderless indicator on the leading side of the status row. Shown only when the thread has an explicit 1–5 priority. Renders cumulative dots (`●○○○○` through `●●●●●`) in a monospaced 9pt font so the string width is stable across levels. Dot color tints by level: 1 blue, 2 green, 3 yellow, 4 orange, 5 red.
- Pinned and favorite markers use an optically smaller 11pt symbol frame and explicit center alignment against the 13pt hidden marker so all three share one visual baseline. Pinned, favorite, and hidden symbols always match the description text's rendered color and opacity, including selection and row dimming. Threads whose tmux sessions are all inactive dim their shared text-and-status container to 70%, including full-color sign emoji and every status-row item; hidden/archiving rows use 50%, and the states compound to 35% so hidden rows remain visually distinct.
- Left-clicking anywhere in the status row passes through to select the thread. Status badges expose their actions only on right-click: priority shows the existing priority choices; favorite, pinned, and hidden offer Remove from Favorites, Unpin, and Unhide; the PR/MR badge opens the numbered PR/MR using the same provider-aware action as the thread controls; and Jira status presents the exact Jira submenu used by the thread context menu. Right-clicking Busy shows its precise activity context; right-clicking Stale also offers the same `Hide`/`Unhide` and `Archive...` actions, icons, and controller entry points as the full thread context menu.
- The `Main worktree` row uses the same neutral capsule background as other rows and is excluded from section-color gradients.
- The main row always uses a dedicated non-customizable `house.fill` icon. When thread icons are enabled it occupies the normal leading icon rail; when they are disabled it remains visible inline immediately after `Main worktree` on the first line. The inline variant uses a compact semibold symbol aligned to the title's first baseline. Its tint always matches the adaptive color of that first-line label.
- `Settings > Threads > Sidebar > Show thread icons` controls whether leading thread icons are rendered. When off, `ThreadCell` hides the arranged leading image view so row text shifts onto the icon rail instead of leaving blank space, and the thread context menu omits `Customize > Icon`.
- Fresh settings show thread icons by default. Existing settings created before `showThreadIcons` was persisted migrate with icons hidden, preserving the earlier icon-free sidebar appearance until the user enables them.
- `Settings > Threads > Sidebar > Show worktree names` controls whether a distinct worktree folder name appears on line 2. It is off by default, including for settings files created before the option existed. When off, line 2 contains only the branch beneath a task description and is hidden when the branch is already the primary line.
- A 6pt top padding row places the first repository at the same vertical inset as a sticky repository header. Every repository uses the same 12pt spacer before its main worktree capsule; the capsule's 4pt top inset makes the visible header-to-capsule gap 16pt.
- Regular thread rows use a two-part vertical stack:
  - line 1 (primary): task description when set; otherwise the branch name.
  - line 2 (secondary / `subtitleLabel`): branch when a description is shown. With `Show worktree names` enabled, a distinct worktree name is appended as `branch · worktree`, or shown alone when no description is present; hidden otherwise. A Jira key detected inside the branch name is highlighted in the primary brand color instead of being repeated as a separate label. A stable 3pt gap separates it from the description even when the status row contains PR or Jira badges. The line renders at 80% of normal content opacity; inactive threads apply that factor again, and hidden-row dimming compounds with both.
  - status row: leading thread markers and trailing PR/MR, Jira, activity, and state badges. PR/MR renders as one combined badge using its short number without a provider prefix, for example `#392 Open` or `!392 Draft`, followed by the optional Jira status badge.
- Row heights are **dynamic** based on actual content (description lines and subtitle) with a default minimum height matching 1 description line + the status row + metadata. When `wideThreads` is enabled, the minimum matches 2 description lines + the same metadata.
- The status row always reserves its 13pt line height, even when it has no visible badges, so title/subtitle spacing and capsule height do not change with thread status. Main worktree rows always reserve their branch subtitle when it is available.
- A thread sign is rendered inline as an emoji prefix on the primary text, separated from the description (or branch fallback) by one space.
- Dirty-branch dots remain orange in both selected and unselected rows; selection must not recolor them with the emphasized white template tint.
- Project repo names use system bold 20pt font.
- Section headers use plain, background-free rows. Their natural-case medium labels align with the leading edge of thread capsules, while the trailing thread count/disclosure control keeps its existing inset. The thread-count badge remains a section-color cue: it uses the section color for its number and a low-opacity version for its background, with the same appearance-aware contrast adjustment as status badges. Sticky section headers use the same plain treatment and alignment.
- No separator divider between project groups; vertical gap (`projectHeaderInterProjectGap = 24pt`) handles spacing.
- Ordinary thread capsules use an 8pt vertical gap. Pinned, normal, and hidden thread groups use a 16pt boundary, separated by blank vertical space only; no divider line is drawn. The main worktree and expanded sections with threads keep 16pt between their final capsule and the following section row, even when that following section is empty. Empty and collapsed sections add no boundary spacing before the section after them because they have no visible final thread.
- The global "Add repository" button is a toolbar icon next to Recently Archived and Settings.
- The add-repo toolbar button opens a 3-item menu: `Create New Repository…`, `Import Existing Repository…`, and `Clone Repository…`.
- When no repositories are configured, the sidebar shows a centered no-content view with direct actions for creating, importing, or cloning a repository.
- `Create New Repository…` selects/creates a target folder, initializes git, seeds an empty initial commit, then registers the project and creates the main thread.
- `Clone Repository…` first asks for the remote URL, then asks for the parent folder where the checkout should be created. The destination folder name is derived from the remote URL (for example `repo` from `git@github.com:owner/repo.git`). After `git clone` succeeds, Magent registers the cloned checkout and creates the main thread.
- During create-repo flow, Magent shows a persistent spinner banner (`Creating repository: <name>`), then replaces it with explicit success (`Repository created: <name>`) or failure status (`Failed to create repository: <name>`) and an error alert.
- Missing repository paths stay visible as project headers instead of being filtered out. The expanded project shows an inline recovery row with `Open New Location` and `Discard` actions; threads are hidden until the repo path is repaired so stale worktree paths are not opened accidentally.
- Missing-repository recovery row content is vertically centered inside the fixed-height row and aligned to the same capsule content rails as thread rows. When Magent becomes active, the sidebar runs a lightweight background existence check for visible project repo paths and reloads only if a project's missing/available state changed.
- **Sticky headers**: After the user scrolls a project header beyond a 12pt activation offset, a floating overlay (`StickyHeaderOverlayView`) pins the project name (and current section, if applicable) at the top of the sidebar. At the top of the list the overlay stays hidden so the first repository's real disclosure control remains usable. Once a project header becomes sticky, it remains visible through inter-project gaps until the next project header passes the same offset and replaces it. Sticky project headers keep the same trailing `+` add-thread button as the normal project row, including the project/agent menu behavior and disabled state while a thread is being created. Their live blur ends exactly at the bottom of the visible project/section rows. Clicking the non-button area of a sticky header smoothly scrolls the sidebar to reveal the actual header row.
- The thread-list scroll view does not show a vertical scrollbar; wheel/trackpad scrolling still works. This keeps the scrollbar from cutting through sticky header blur.
- **Selected-thread jump capsule**: When the selected thread is outside the visible thread-list viewport, a floating capsule appears near the bottom of the thread list (inside the sidebar's thread area, not over the changes panel). It shows title (prefer task description, fallback to worktree name), the thread icon when `showThreadIcons` is enabled, and a directional arrow (`up`/`down`) indicating where the row is relative to the viewport. Clicking it centers the selected thread row. The capsule fades/slides in/out, and after scrolling completes the target row gets a brief pulse.
- The archive icon (`archivebox.fill`) appears in the trailing area, vertically centered against the title/subtitle text block rather than the status row below it. Clicking it must not select the row — `SidebarOutlineView.mouseDown` intercepts clicks on the archive button directly.

## Implementation Notes

- Capsule geometry is defined in `AlwaysEmphasizedRowView`:
  - `capsuleLeadingInset` / `capsuleTrailingInset` — inset from row edges to capsule border. The overlay vertical scroller floats over the trailing inset region, so the capsule itself is never visually clipped. To avoid capsule-width jitter when the scroller appears/disappears (e.g. on window deactivate/reactivate, or on mouse hover expanding the overlay scroller), `refitOutlineColumnIfNeeded` sizes the column from `scrollView.bounds.width` rather than `contentView.bounds.width`. The outline view's `columnAutoresizingStyle` is set to `.noColumnAutoresizing` and the column's `resizingMask` is `[]` — otherwise AppKit's own last-column autoresize shrinks the column whenever the clip view narrows transiently (overlay-scroller hover reserves a few pixels) and beats our manual refit to it.
  - `capsuleVerticalInset` — vertical inset.
  - `capsuleBorderWidth` / `capsuleBorderInset` — border stroke width and half-width.
  - `capsuleContentHPadding` / `capsuleContentVPadding` — shared capsule content padding defaults. Thread rows keep the 12pt horizontal inset but use an explicit 8pt top/bottom vertical layout.
  - `capsuleCornerRadius` — 8pt.
- Shared constants in `ThreadListViewController`:
  - `sidebarHorizontalInset` = capsuleLeadingInset + borderInset + contentHPadding — leading content rail.
  - `sidebarTrailingInset` — trailing content rail (same derivation from trailing side).
  - `capsuleAlignedLeading` / `capsuleAlignedTrailing` — non-thread row alignment (project/section headers).
- Sidebar and changes-panel scroll views use `NonFlashingScrollView`. The main thread list keeps its vertical scroller disabled entirely so sticky-header blur owns the full trailing edge. The changes panel still gates `flashScrollers()` on recent local `scrollWheel` input, but `reflectScrolledClipView(...)` is always forwarded to `super` so AppKit keeps tiling/geometry in sync during programmatic scroll restore and reload paths.
- Top and bottom sidebar spacing use explicit root items: `SidebarTopPadding` matches the first repository to the sticky-header top inset, while `SidebarBottomPadding` keeps end-of-list scroll space deterministic regardless of changes-panel visibility.
- Outline view uses `indentationPerLevel = 0`. All indentation is managed via capsule-relative padding in `ThreadCell`.
- `AlwaysEmphasizedRowView.drawBackground(in:)` handles all selection/state drawing (not `drawSelection`). `selectionHighlightStyle = .none` on the outline view suppresses AppKit's own selection rect.
- `AlwaysEmphasizedRowView.isSelected.didSet` pushes `backgroundStyle` to child cell views.
- `ThreadCell.configureAsMain(...)` owns the dedicated main-row content state (fixed title/subtitle behavior and fixed `house.fill` icon). `AlwaysEmphasizedRowView` owns the capsule visual treatment for main rows.
- Dynamic row heights computed in `heightOfRowByItem` using `ThreadCell.estimatedDescriptionLineCount` (text width estimation) and `ThreadCell.sidebarRowHeight(descriptionLines:hasSubtitle:narrowThreads:)`.
- The archiving overlay is owned by `AlwaysEmphasizedRowView`, covering the full row bounds.
- Archive preflight failures (for example dirty-worktree / ignored-file refusals) must clear `isArchiving` immediately so this overlay never remains stuck on a live thread row.
- `ThreadCell` has one full-width status row inside its text stack, 8pt after the title/subtitle block and 8pt above the capsule's bottom content edge; the text block begins 8pt below the top content edge. Its trailing edge is constrained directly to the capsule's trailing content rail rather than inheriting the width of the description/metadata column, so trailing indicators stay aligned regardless of text length. Its leading stack contains priority, Jira status, and PR/MR status. Its trailing stack contains local state indicators, ending with the activity, stopped-session, favorite, and pinned group, with a flexible spacer between the leading and trailing stacks. Other status items are borderless and do not inherit the row's selected/completed/waiting border treatment. Both groups use `detachesHiddenViews = true` so indicators collapse independently. `configurePriority(_:)` accepts `Int?` and hides the indicator for `nil`/out-of-range values.
- The entire status row follows the same opacity treatment as other content: 70% for inactive threads, 50% for hidden/archiving threads, and 35% when both states apply.
- Busy border animation is a rotating conic gradient (`CAGradientLayer` with `.conic` type) masked to the capsule border stroke via a `CAShapeLayer`. Unselected rows show only a short bright accent-colored arc (~16% of the circumference) above the section-color corner marker; selected rows retain a subtle white gradient for contrast. Managed by `AlwaysEmphasizedRowView.startBusyBorderAnimation()`.
- All busy threads share a single animation epoch (`sharedAnimationEpoch`) set when the first thread becomes busy. Busy border rotation uses this epoch as its `beginTime`, so all busy threads animate in phase with each other. The epoch is never reset, so it persists across the app's lifetime.
- Spinner indicators were removed from `ThreadCell`'s trailing stack — the animated border replaces them.
- `StickyHeaderOverlayView` is a standalone view added as the topmost subview of `ThreadListViewController.view`. It mirrors project/section header styling (same fonts, insets, colors) and the project row's trailing add-thread button, but does not include disclosure buttons. The overlay height is managed by an external constraint updated by `updateStickyHeaders()`, which fires on every clip-view bounds change and after `reloadData()`. One full-strength `NSVisualEffectView` with `.popover` material covers exactly the top inset and visible project/section rows; do not append a fade/spacer region below them. Header height changes disable implicit animations so the overlay appears immediately instead of filling in over time. Click targets on the project/section regions fire `onProjectClicked`/`onSectionClicked` callbacks that animate-scroll the outline view to the actual header row (with the section offset by the complete sticky-project height, including its top inset); the sticky project `+` button uses the same `addThreadForProjectTapped(_:)` path as the normal project row. Keep the button's `objectValue` in sync with the sticky project id when configuring it, and route `hitTest` hits inside the button back to the `NSButton` so the overlay's header-click handler cannot swallow add-thread clicks.

## Gotchas

- When displaying branch and worktree names together, check for equality first — if the same, show once.
- Keep the main-row default capsule background identical to ordinary neutral thread backgrounds; its fixed home icon is the only persistent visual distinction.
- `SidebarProjectMainSpacer` is skipped entirely when `projectHeaderToMainRowGap = 0` — inserting a 0-height spacer row crashes `NSOutlineView`.
- Do not rely on `NSScrollView.contentInsets` for overlay-aware bottom spacing in this sidebar. Effective behavior changes with sibling panel visibility; use explicit content padding rows (`SidebarBottomPadding`) instead.
- Jira ticket highlighting must use the key actually detected in the branch name. An explicitly associated Jira key that is absent from the branch must not highlight unrelated text.
- CALayer colors from dynamic NSColor assets must be resolved inside `performAsCurrentDrawingAppearance`. `NSColor(resource:).withAlphaComponent(_:)` can snapshot the wrong drawing context at call time. Always create derived colors AND access `.cgColor` inside the `effectiveAppearance.performAsCurrentDrawingAppearance { }` block.
- **Never mutate `anchorPoint` on an `NSView`-backed `CALayer`** to center a scale animation. Changing `anchorPoint` without a matching `position` adjustment displaces the entire view. Instead, bake the centering translation into each `CATransform3D` keyframe: `translate(w/2, h/2) → scale → translate(-w/2, -h/2)`.
- **`backgroundStyle = .emphasized` auto-inverts adaptive colors to white.** `AlwaysEmphasizedRowView.isSelected.didSet` must only push `.emphasized` in dark mode. In light mode, push `.normal` even when selected — otherwise AppKit makes all `.labelColor`/`.secondaryLabelColor` render white against the pale accent fill, making text and icons invisible.
- **Light mode color readability**: `systemCyan`, `systemMint`, and `systemYellow` are illegible on white/light backgrounds even at full opacity. In light mode, map these to `systemBlue`, `systemTeal`, and `systemOrange` respectively. `NSColor(resource: .surface)` is pure white in light mode — never use it as a visible surface background; use `NSColor(resource: .appBackground)` or an explicit sRGB value instead.
- **Always use `effectiveAppearance.bestMatch(from: [.aqua, .darkAqua]) == .darkAqua`** for dark-mode detection, never `effectiveAppearance.name == .darkAqua`. `.name` can be any of `.darkAqua`, `.vibrantDark`, `.accessibilityHighContrastDarkAqua`, `.accessibilityHighContrastVibrantDark` etc., and an exact `==` comparison against `.darkAqua` silently fails when Accessibility → Increase Contrast is enabled or when vibrancy variants are in play, making the code treat dark mode as light. `bestMatch` normalizes all dark variants to `.darkAqua`.
- Create-repo bootstrap must not depend on user-level git commit config. The seed commit path should pass transient `-c` overrides for identity and signing (`user.name`, `user.email`, `commit.gpgsign=false`) and skip local hooks (`--no-verify`) to avoid silent failures from machine-specific git config.
- Do not discard git stderr in create/import flows. Failure paths should surface the underlying git message to the user (alert/banner) so "does nothing" states are diagnosable.
- The add-repository menu can be opened from the icon button or by selecting the `SidebarAddRepoRow`; the row-selection path passes a synthetic sender, so menu positioning and sheet presentation must resolve a real outline row/cell anchor instead of relying on `sender.window`.
- Moved-repo recovery must update `Project.repoPath`, remap the main thread path, remap thread worktree paths under the old default worktrees base, and rewrite both active and archived thread records. If the project used the default suggested worktrees base, move that base with the repo; if it used a custom base, preserve it. Discarding a missing project removes the project and all active/archived thread records from Magent only, not files on disk.
- For sidebar/diff-panel scroller behavior, key-window checks are not sufficient in multi-Mac setups with Universal Control. Gate reveal on actual local scroll input instead of focus/hover state.

## Thread Row Naming/Description Contract

For non-main threads, render description on line 1 only when present; prefix its primary text with the thread sign plus one space when a sign is set. If no description exists, apply the same prefix to the branch fallback. Keep branch/worktree info on the branch-facing line with dot-separated segments (`branch · worktree · PR`). Keep dirty dot attached to the branch/worktree line, not the description line. Tooltip sections must skip missing fields/statuses. Generated task descriptions prefer 2-8 words and naturally cased text (do not force Title Case). Longer descriptions are allowed and should truncate with a trailing ellipsis when they exceed visible row lines.

## Auto Icon Assignment

AI-driven work-type icon assignment is allowed only when `AppSettings.autoSetThreadIconFromWorkType` is enabled and `MagentThread.isThreadIconManuallySet` is false. Any user-triggered icon change must mark `isThreadIconManuallySet = true`, including no-op re-selections of the current icon.
